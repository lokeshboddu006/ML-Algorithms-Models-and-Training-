## 💡 Core Philosophy

> **"A model cannot compensate for poor understanding of the data. Don't just call `.fit()` — master the mechanics behind the convergence."**

Machine learning is often reduced to high-level library calls. While that makes experimentation easy, it hides the algorithmic mechanics, cost functions, and optimization techniques that make machine learning work.

This repository takes a practical approach:

```text
  Understand Data ──► Data Cleaning & EDA ──► Feature Engineering ──► Model Training ──► Performance Evaluation ──► Production Insights
```

## 📚 Machine Learning Taxonomy

<details open>
<summary><b>🧹 Data Engineering & Preprocessing</b></summary>
<br>

* **Statistical Distributions:** Skewness, Kurtosis, Interquartile Range (IQR).
* **Data Sanitization:** Missing value strategies, duplicate resolution, type coercion.
* **Feature Processing:** One-Hot Encoding, Ordinal Encoding, Robust Scaling, Min-Max Normalization.
* **Feature Relationships:** Pearson & Spearman correlation heatmaps, pair plots, collinearity audits.

</details>

<details open>
<summary><b>📈 Regression Models</b></summary>
<br>

* **Ordinary Least Squares (OLS):** Closed-form analytical solutions vs. iterative gradient updates.
* **Multiple & Polynomial Regression:** Capturing non-linear decision manifolds.
* **Residual Diagnostics:** Homoscedasticity audits, Q-Q plots, variance breakdown.

</details>

<details open>
<summary><b>🎯 Classification Models</b></summary>
<br>

* **Logistic Regression:** Sigmoidal activation, binary cross-entropy optimization, log-odds interpretation.
* **Decision Boundaries:** Hyperplane separation in multidimensional feature spaces.
* **Multi-class Strategies:** One-vs-Rest (OvR) and One-vs-One (OvO) architectures.

</details>

<details open>
<summary><b>🌳 Tree-Based Models</b></summary>
<br>

* **Splitting Criteria:** Formulations for Gini Impurity and Shannon Entropy / Information Gain:

$$\text{Gini}(p) = 1 - \sum_{i=1}^{C} p_i^2 \qquad \text{Entropy}(S) = -\sum_{i=1}^{C} p_i \log_2(p_i)$$

* **Tree Dynamics:** Recursive binary splitting, cost-complexity pruning, depth constraints to avoid overfitting.

</details>

## 📐 Scientific Evaluation Matrices

### 🔹 Regression Evaluation Framework

| Metric | Mathematical Focus | Primary Objective |
| --- | --- | --- |
| **MAE** | $\frac{1}{n}\sum \Vert{}y - \hat{y}\Vert{}$ | Measures average absolute error without outlier bias. |
| **MSE** | $\frac{1}{n}\sum (y - \hat{y})^2$ | Penalizes large deviations quadratically. |
| **RMSE** | $\sqrt{\text{MSE}}$ | Yields error metrics directly in target variable units. |
| **$R^2$ Score** | $1 - \frac{SS_{\text{res}}}{SS_{\text{tot}}}$ | Quantifies the proportion of explained variance. |

### 🔹 Classification Evaluation Framework

| Metric | Mathematical Focus | Primary Objective |
| --- | --- | --- |
| **Accuracy** | $\frac{TP + TN}{TP + TN + FP + FN}$ | Overall correctness across balanced class distributions. |
| **Precision** | $\frac{TP}{TP + FP}$ | Minimizes False Positives (spam detection, quality control). |
| **Recall** | $\frac{TP}{TP + FN}$ | Minimizes False Negatives (medical diagnoses, fraud detection). |
| **$F_1$ Score** | $2 \cdot \frac{P \cdot R}{P + R}$ | Harmonic mean balance between Precision and Recall. |
| **Confusion Matrix** | Visual Contiguity Grid | Complete granular mapping of true vs. predicted classes. |

```text

2. git checkout -b feature/your-algorithm
3. Implement + document (math intuition > just code)
4. git commit -m "Add: <Algorithm Name> from scratch"
5. git push origin feature/your-algorithm
6. Open a Pull Request
```

**Good first contributions:**
- 📓 Add a new notebook for an unchecked roadmap item
- 🐛 Fix a bug or numerical instability in an existing implementation
